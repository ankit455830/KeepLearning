java memory model
The Java Memory Model is a specification that describes:

How Java threads interact through memory.

How changes made by one thread become visible to others.

How concurrency issues like race conditions, reordering, and stale reads are handled.

It ensures correct execution of multithreaded Java programs even on modern CPUs and compilers that can reorder instructions.

Idempotency (VERY IMPORTANT for finance)

“All financial operations are idempotent to prevent double charging.”

Example:

Each transaction has a unique transactionId

Duplicate requests are safely ignored

      inventoryServiceCB:
        failure-rate-threshold: 50        # % failures to open circuit

        minimum-number-of-calls: 5
        wait-duration-in-open-state: 10s   # stay OPEN for 10s
        permitted-number-of-calls-in-half-open-state: 2
        automatic-transition-from-open-to-half-open-enabled: true
  retry:

        max-attempts: 3
        wait-duration: 500ms

  bulkhead:
    instances:
      inventoryBulkhead:

		@Service
public class InventoryService {

    @CircuitBreaker(
        name = "inventoryServiceCB",
        fallbackMethod = "fallbackInventory"
    )
    public String checkStock(String productId) {
        // Simulating downstream failure
        if (productId.startsWith("fail")) {
            throw new RuntimeException("Inventory service down");
        }
        return "Stock available for product " + productId;
    }
